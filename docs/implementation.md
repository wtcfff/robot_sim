# 实现与迁移记录

## 迁移依据

参考源为 `/home/xsl/桌面/Wheel-Legged-Gym-master`。复制资源与所需实现，原目录未修改。`tests/test_framework.py` 在参考目录可用时对比 `domain_rand`、`noise`、`commands`、`control`、`init_state`、`rewards`、`normalization`、`sim` 配置，并通过 Python 语法树对比基类和 Wheelleg 类的所有 `_reward_*` 及 `compute_reward` 实现。该测试已通过；参考目录不存在时仅跳过来源比对，其余检查仍运行。

任务保持 32 维基础观测、8 维动作和 259 维特权观测。普通 PPO 的价值输入强制使用基础观测，避免因环境生成了特权观测而意外使用。历史仅在 runner 一侧建立，环境遗留历史长度设为零。

通用地形默认全部九类；Wheelleg 显式保留参考任务的 `[0,1,2,5]` 启用集合。地形生成公式及公共分辨率/尺寸迁自参考项目，但列分配改为每类至少一列，再按权重分配余数；斜坡方向选取也随列分配改变。因此不宣称新旧地形地图在同一种子下逐像素一致。公平性针对本项目内部三种方法成立，需要使用同样的任务配置和种子。

## 奖励迁移核对

本次迁移不设计新奖励，不改变正负号、权重、启用状态或函数公式。作用范围、核函数、权重与裁剪都继续取自任务与基类；零权重项保留定义但按原机制不参与计算。

| 类别 | 作用范围与核函数 | 代表权重与范围 | 行为收益与代价 |
|---|---|---|---|
| 速度/偏航跟踪 | 每个策略步；`exp(-error²/0.25)` | 前向 `1.0`，偏航 `0.5`；原始核在 `(0,1]` | 平滑跟踪信号；误差过大时信号弱，可能与能耗/平滑惩罚冲突 |
| 高度跟踪 | 每步；`exp(-height_error²/0.01)` | `1.0`；原始核在 `(0,1]` | 支持指令高度；可能增加关节用力 |
| 姿态、速度、加速度、力矩 | 每步；平方和 | 保留任务全部负权重，如姿态 `-5.0`、腿力矩 `-0.0001`、轮力矩 `-0.0002` | 抑制抖动和失稳；过强会牺牲快速跟踪 |
| 机械功率 | 每步；`sum(abs(torque * velocity))` | `-2e-5` | 约束能耗；可能限制加速和越障 |
| 动作变化 | 每步；腿/轮动作一阶差分平方，以及腿动作二阶差分平方 | `-0.01` / `-0.02` / `-0.01` | 平滑控制；可能增加响应滞后 |
| 关节/速度/力矩软限制与碰撞 | 超出软阈值或发生接触时；分段惩罚/接触计数 | 保留 `dof_pos_limits=-1.0`、`dof_vel_limits=-0.1`、`torque_limits=-0.1`、`collision=-1.0` | 减少越限和碰撞；裁剪后严重越限的惩罚会饱和 |
| 静止与漂移 | 小运动指令时生效；静止为速度高斯核，漂移为归一化前向速度平方 | `stand_still=1.0`、`stand_still_drift=-1.0` | 提高静止能力；切换阈值附近需关注行为连续性 |
| 轮距与轮中心偏移 | 每步；带门控/阈值的归一化惩罚 | `wheelleg_track=-1.0`、`wheel_base_rel_pos=-0.5` | 约束站姿与相对几何；可能限制恢复或越障姿态 |

完整数值以 `wheelleg_config.py` 的 `rewards` 为准。每项先乘 `weight * policy_dt`，再裁剪：普通项为 `[-dt,dt]`，`stand_still` 为 `[-2dt,2dt]`。当前 `dt=0.01 s`。总奖励是各项和，`only_positive_rewards=False`，没有额外的总奖励非负裁剪；当前终止奖励权重为零。总范围取决于启用项数量及各项原始符号，不能将单项上限当作总上限。

已经通过源代码与配置等价检查，并实际运行采样/更新；这证明迁移可执行，奖励组合对最终行为的优劣仍需要完整训练和消融实验验证。

## 训练层

新增共享 runner、独立任务配置、轨迹缓存、PPO 更新及 HIM/WAQ 辅助更新。普通 PPO 不使用历史或特权价值输入；三种方法的奖励、随机化和仿真参数来自同一个任务工厂。

启动/重置直接返回真实初始状态的观测，不再暗中执行一个零动作控制步。历史最旧到最新排列，当前帧计入历史；每个环境单独处理采样间隔和重置。重置前后保存不同观测，超时/边界截断从重置前的最终状态估计价值，广义优势递推在所有回合边界停止。估计器不将跨回合状态组成训练对。这些与参考旧 runner 的差异可能影响收敛，因此与参考训练曲线比较时需要单独解释。

HIM 辅助项为速度均方误差与交换原型分配交叉熵，交叉熵对原型求和、对样本取均值；WAQ 为速度均方误差、下一帧观测重构误差与 beta 加权的潜变量 KL。两者估计器单独优化，策略损失不反向传播到估计器。共同 PPO 默认值可在 `robot_sim/config.py` 统一修改。

**对训练端**：统一数据流和超时语义，历史方法增加历史存储/辅助梯度消耗；已验证有限值和更新链路，稳定性、收敛速度与最终性能未知。固定随机种子不保证 GPU 物理完全确定。

**对网络端**：改变网络输入路由与训练目标；只支持本框架规格的 PT，未实现直接导入参考项目旧 checkpoint。**对部署端**：训练差异会间接影响策略行为；部署仍须使用对应模型的历史和缩放配置，需独立验证性能。

## 网络层

基础策略输出维度对同一任务一致。PPO 策略/价值分别使用 32 维观测；HIM/WAQ 的策略编码器使用 5×32 维历史，输出 3 维速度和 16 维表示，与当前观测拼接后策略 MLP 输入为 51 维，价值输入为 259 维。默认共享策略隐藏层 `[128,64,32]`、价值隐藏层 `[256,128,64]`，可在统一训练配置中调整。

HIM 使用归一化表示、可学习原型与目标观测编码网络。WAQ 重构路径采用随机重参数化；策略路径使用潜变量均值，使 PPO 对同一输入重算概率时和 ONNX 推理时使用一致上下文。**WAQ 当前不含 AdaBoot，属于明确标识的基准变体**，不宜将其结果直接标注为原论文完整 DreamWaQ 的复现结果。HIM 同样未完成原论文实现逐项核验。

**对网络端**：新增估计器与训练分支，三种方法权重不可互换；任务基础观测和动作的定义不变。**对训练端**：历史与辅助目标增加计算量，模型容量也不同；比较结果包含信息量及容量差异，不能只归因为 PPO 优劣。**对部署端**：HIM/WAQ 必须一起执行编码器，增加历史输入和推理成本；实际延迟未做基准测试。

## 部署层

PT 正常保存，ONNX 在单独脚本中按保存规格重建与转换。转换校验动态 batch=1 和 7 的数值，历史与观测维度来自 PT。模型旁完整 YAML 明确记录顺序、方向、偏置、单位缩放、限幅、控制周期、名义增益、初始状态与历史填充；目标 XML/关节映射单独放在脚本配置目录。

MuJoCo 运行器使用 YAML 中的映射构建观测并逐物理步计算控制力矩，关节速度位置差分与训练规则一致。可显式配置常数块补齐占位观测，不自动推测缺失传感器。当前目标执行器要求单位传动比；其他传动比需增加相应转换。启动不执行隐式稳定等待步。实际机器人也需要按 YAML 对齐传感器坐标、时间同步和控制器，但本次未实现真实硬件通信。

**对部署端**：新增 ONNX、显式迁移文件、Isaac Gym 键盘播放和 MuJoCo 执行接口。**对训练端无直接影响**：导出/部署脚本不修改训练配置和 PT；模型效果仍需通过部署试验间接验证。**对网络端无直接影响**：转换不改变权重，推理用完整编码器和策略；精度误差已做有限随机输入验证，未覆盖所有状态。

## 实际验证记录

2026-11-17，在 `leggedgym` 专用环境与 GPU 上完成：

- 8 个自动检查全部通过，含 GPU 回合重置/超时与观测控制转换。
- PPO/HIM/WAQ 各 8 个并行环境、每轮 4 步、1 轮更新（验证时 1 epoch、2 个 minibatch、小地形）；损失有限并生成 PT。该设置仅用于链路检查。
- PPO PT 从第 1 轮恢复后完成第 2 轮更新，优化器/配置加载成功。
- 三种模型转换 ONNX，随机输入与 PyTorch 最大绝对误差均小于 `1e-7`。
- PPO/WAQ 在 MuJoCo 运行 30 个策略步、HIM 运行 20 个策略步，状态有限。
- WAQ PT + ONNX 在 Isaac Gym 平地运行 5 个策略步。
- 九类地形的 0/9 难度预览共 18 块，生成与无窗口循环通过。
- PPO 固定评估 4 个环境、10 步，JSON 输出成功。

短程产物位于 `logs/validation/wheelleg/`，按 `ppo`、`him`、`waq`、`ppo_resume` 区分方法和续训检查。这里的 PT 是随机初始附近的检查模型，不能作为已训练策略使用。测试输出保存在 `logs/validation/wheelleg/test_results.txt`。普通训练仍默认输出 `logs/<task>/<method>/<时间>/`。

资源与目录核查：`resources/robots/wheelleg/urdf/scene.xml` 和 `wheelleg.xml` 均已迁移，与参考文件逐字节一致。sim2sim 从模板指定的 `scene.xml` 加载，场景包含机器人 XML 并通过相对目录引用网格。验证目录调整仅更新现有导出 YAML 的 `source_checkpoint` 路径及文档，PT/ONNX 文件内容和训练默认保存规则均不变。训练层：对训练端无直接影响，奖励、采样及优化参数不变。网络层：对网络端无直接影响，结构、输入输出与权重不变。部署层：调整验证产物路径；使用新 YAML 路径启动，需复核场景和模型仍可加载。

尚未验证：长程收敛、三种方法的统计性能、4096 并行规模、图形窗口和实际键盘事件、真实机器人、完整 sim2real 物理精度。当前 GPU 短程仿真与 MuJoCo 有限状态检查不能替代这些验证。
